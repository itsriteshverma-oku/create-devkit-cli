01 Introduction & Overview

What is create-devkit-cli?

create-devkit-cli is an npm package that provides a command-line interface (CLI) for scaffolding new projects interactively. It works similarly to popular tools like create-react-app, create-vite, or create-next-app.

When a developer runs npx create-devkit-cli, an interactive terminal wizard launches that asks a series of questions and then generates a complete, ready-to-code project with all files, folders, and configurations in place.

What Problem Does It Solve?

  • Saves time — No need to manually create folders, write config files, or set up boilerplate code
  • Consistency — Every project starts with best-practice file structure
  • Beginner-friendly — Interactive prompts guide users through project setup
  • Multi-template — One tool for 4 different project types

02 Installation & Quick Start

Method 1 — Run Without Installing (Recommended)

Using npx, you can run the tool directly without installing it globally:

npx create-devkit-cli

npx downloads the package temporarily, executes it, and cleans up. Perfect for one-time use.

Method 2 — Install Globally

Install the package globally so the create-devkit-cli command is always available:

npm install -g create-devkit-cli

# Now run from anywhere:
create-devkit-cli

Method 3 — Clone & Link Locally (For Development)

# Clone the source code
git clone <your-repo-url>
cd create-devkit

# Link it globally
npm link

# Now run from anywhere:
create-devkit-cli

Module System

This package uses CommonJS (CJS) module system — require() and module.exports. This is specified in package.json as "type": "commonjs".

ℹ️ Why CommonJS?

CommonJS is the most compatible module system in Node.js. It works with all Node.js versions ≥ 16 without any extra configuration. Some dependencies (like chalk v5+ and ora v6+) switched to ESM-only, so we use chalk@4 and ora@5 which are the last CJS-compatible versions.

04 How It Works — Complete Flow

Step 1: Command Execution

When you run npx create-devkit-cli, npm finds the package, downloads it, and executes the file specified in the "bin" field of package.json:

"bin": {
  "create-devkit-cli": "bin/cli.js"
}

The first line of bin/cli.js is a shebang: #!/usr/bin/env node. This tells the OS to execute this file using Node.js.

Step 2: Argument Parsing (Commander.js)

bin/cli.js uses Commander.js to parse any command-line arguments:

program
  .name("create-devkit")
  .version(pkg.version, "-v, --version")

program
  .command("new [project-name]", { isDefault: true })
  .option("-t, --template <template>", "Project template")
  .action(async (projectName, options) => {
    await runWizard({ projectName, template: options.template });
  });

If the user passes my-app or -t react, those values are pre-filled and the corresponding prompts are skipped.

Step 3: Interactive Prompts (Inquirer.js)

src/prompts.js displays a beautiful banner and asks 5 questions:

#QuestionTypeDefault
1📁 Project nameText inputmy-app
2🎨 Template selectionList (arrow keys)—
3📦 Package managerListnpm
4🔧 Initialize git?Yes/No confirmYes
5📥 Install dependencies?Yes/No confirmYes

Step 4: Project Scaffolding (scaffold.js)

After collecting answers, scaffold.js performs these operations in order:

  1. Check if the target directory already exists (exits with error if yes)
  2. Create the project directory using fs.mkdirSync()
  3. Fetch template files from src/templates/
  4. Write all files to the new directory
  5. Git init (optional) — runs git init + creates .gitignore
  6. Install dependencies (optional) — runs npm install / yarn / pnpm install
  7. Print success banner with next steps

Each step shows a spinner (using Ora) that shows ⏳ while running and ✔ on success.

Step 5: Output

✔ Created my-app/
✔ Scaffolded react template
✔ Git repository initialized
✔ Dependencies installed

  ✔  Project ready! Happy hacking! 🚀

  Next steps:

    cd my-app
    npm run dev

⚠️ Important — The "bin" field

The "bin" field is what makes this an executable CLI tool. When installed globally (npm i -g), npm creates a symlink from the system PATH to bin/cli.js, making create-devkit-cli a runnable command.

📄 bin/cli.js

The entry point. Contains:

  • Shebang line — #!/usr/bin/env node tells the OS to run with Node.js
  • Commander.js program — defines the new command (set as default)
  • Options — --version, --help, --template
  • Help text — Custom examples shown with --help

📄 src/prompts.js

The interactive wizard. Contains:

  • TEMPLATES array — 4 template choices with icons and descriptions
  • PKG_MANAGERS array — npm/yarn/pnpm choices
  • runWizard() function — displays banner, builds question list, runs inquirer.prompt(), and calls scaffold()
  • Validation — project name validation (alphanumeric + hyphens only)
  • Smart skipping — if args are pre-filled via CLI, those prompts are skipped

📄 src/scaffold.js

The core engine. Contains the scaffold() function with:

  • Directory check — prevents overwriting existing folders
  • File writing — iterates template files and writes to disk using fs
  • Git init — runs execSync("git init") and writes .gitignore
  • Dependency install — runs the chosen package manager's install command
  • Spinners — Ora spinners for each operation (creating, scaffolding, installing)
  • Error handling — try/catch with colored error messages

📄 src/templates/index.js

A simple registry/router that maps template names to their functions:

function getTemplateFiles(template, projectName) {
  switch (template) {
    case "vanilla": return vanillaTemplate(projectName);
    case "react":   return reactTemplate(projectName);
    case "node-api": return nodeApiTemplate(projectName);
    case "cli-tool": return cliToolTemplate(projectName);
  }
}

Each template function returns an object where keys are file paths and values are file contents as strings.

💡 How templates work internally

Each template file (e.g., vanilla.js) exports a function that takes the project name and returns an object. The keys are relative file paths, and the values are the file contents as strings. The scaffold engine iterates over this object, creates directories with fs.mkdirSync, and writes files with fs.writeFileSync.

07 Dependencies Explained

Runtime Dependencies (4)

1. Commander.js (^12.1.0)

The most popular CLI framework for Node.js. It handles:

  • Command definition — program.command("new")
  • Option parsing — --version, --template react
  • Auto-generated help — --help flag
  • Positional arguments — create-devkit-cli my-app

2. Inquirer.js (^8.2.7)

Interactive CLI prompt library. Supports:

  • input — text input (project name)
  • list — arrow key selection (template, package manager)
  • confirm — yes/no questions (git init, install deps)
  • Built-in validation and filtering
⚠️ Version note

We use Inquirer v8 (not v9+) because v9+ switched to ESM-only modules, which are incompatible with our CommonJS setup. The API is identical.

3. Chalk (^4.1.2)

Terminal string styling. Provides chainable methods for coloring text:

chalk.bold.cyan("text")     // Bold cyan text
chalk.red("error")          // Red text
chalk.dim("muted text")     // Dimmed text
chalk.green("✔ success")    // Green text

Used throughout for the banner, prompts, spinners, and success messages.

4. Ora (^5.4.1)

Elegant terminal spinner library. Shows loading state during async operations:

const spinner = ora("Scaffolding…").start();
// ... do work ...
spinner.succeed("Done!");   // ✔ Done!
spinner.fail("Error!");     // ✖ Error!
spinner.warn("Warning!");   // ⚠ Warning!
